## How to run it

| What | Command |
|---|---|
| Validate the bundle against the app (no writes) | `npm run check:360` |
| Regenerate engine data after a bundle change | `node scripts/import-catalogue-360.mjs` |
| Engine tests (20, incl. the 12 bundle scenarios) | `npm test` |
| Preview a plan for a context | `node scripts/rules360.mjs preview first-birthday '{"guests":120}'` |
| Load catalogue + matrix into the DB | `node --env-file=.env scripts/import-catalogue-360.mjs --apply` |
| Publish edited rules (validates + runs tests first) | `node --env-file=.env scripts/rules360.mjs publish --notes "…"` |
| Roll back / history | `rules360.mjs rollback <version>` · `rules360.mjs history` |

`supabase/seed/catalogue360.json` is regenerated by the import and not committed.

## Rule tuning

Edit `src/customer/data/rules360.js` (or an exported JSON), bump
`RULES_VERSION`, run `npm test`, then `publish`. The app loads the published
version at start (`lib/eventPlans.js → loadRules`), validates it, and falls
back to the bundled rules if none is published or it is invalid.
